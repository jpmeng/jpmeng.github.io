How to create a virtual machine using qemu+kvm

Host environment setup

To create virtual machines using qemu+kvm under Rocky Linux, we need to install the necessary packages and set up the environment.

First, we need to install the required packages and start the libvirt service:

sudo dnf install -y virt-install libvirt qemu-kvm libguestfs-tools
sudo systemctl enable --now libvirtd

If a personal computer is used, probably not much space is allocated for the /var directory, which is the default location for storing virtual machine images. To avoid running out of space, we can create a directory under /home to store the images and give libvirt/qemu permission to access it:

cd /home
sudo mkdir vms
sudo chown $USER:$USER vms
sudo chmod 711 vms
# tell selinux to allow libvirt to access the directory and files therein
sudo semanage fcontext -a -t virt_image_t "/home/vms(/.*)?"
# apply the new context to the existing files and directories
sudo restorecon -R -v /home/vms

Through my test, 711 is minimum permission for the directory /home/vms to allow libvirt to access it. If it is 700, libvirt will complain about permission denied when trying to access the image file in that directory.

For convenience, we can make our own user a member of the libvirt group [1], so that we can manage virtual machines without sudo:

sudo usermod -a -G libvirt $USER

To ensure that the new group membership is effective, we can log out and log back in.

We also need to set the LIBVIRT_DEFAULT_URI environment variable to point to the system-wide libvirt instance qemu:///system. Otherwise, the default is qemu:///session pointing to the user session.

export LIBVIRT_DEFAULT_URI="qemu:///system"

We can add the above line to our shell profile (e.g., ~/.bashrc or ~/.zshrc) to make it permanent.

Network setup

Next, we need to prepare the network for the virtual machines. By default, libvirt provides a NATed network called “default”. We can start it and set it to autostart:

virsh net-start default
virsh net-autostart default

If somehow the default network is not available, we can create it using the default XML configuration file provided by libvirt:

virsh net-define /usr/share/libvirt/networks/default.xml

At this moment it is sufficient to use the default network for our virtual machines. For more advanced network configuration, please refer to the official documentation [2-3].

Image preparation

To prepare the image for the virtual machine, we could take advantage of the cloud image provided by Rocky Linux, which is a qcow2 image with cloud-init pre-installed.

We can then utilise the virt-customize tool to customize the image, such as setting the password for the root user, creating a test user, and resizing the image to have enough space for the root partition. Below is an example of how to do this:

# let virt-customize access the image file directly without using libvirt, which is faster and more efficient
VM_NAME=$1
export LIBGUESTFS_BACKEND=direct
IMAGE_DIR="/home/vms"
# assumming the cloud image is already downloaded to $IMAGE_DIR, and its name is Rocky-9-GenericCloud-Base.latest.x86_64.qcow2
IMAGE="$IMAGE_DIR/Rocky-9-GenericCloud-Base.latest.x86_64.qcow2"
cp "$IMAGE" "$IMAGE_DIR/$VM_NAME.qcow2"
# Resize the image to 40G to have enough space for the root partition
qemu-img resize "$IMAGE_DIR/$VM_NAME.qcow2" 40G
# Customize the image
# Replace TESTUSER and TESTUSERPASSWORD with your own username and password for the test user
# The root user will be locked and cannot be used to log in
virt-customize -a "$IMAGE_DIR/$VM_NAME.qcow2" \
    --run-command "passwd -l root" \
    --run-command "usermod -L root" \
    --edit '/etc/passwd: s/^root:x:0:0:root:\/root:\/bin\/bash/root:x:0:0:root:\/root:\/sbin\/nologin/' \
    --hostname "$VM_NAME" \
    --password TESTUSER:password:TESTUSERPASSWORD \
    --run-command "useradd -m -G wheel TESTUSER" \
    --edit '/etc/default/grub: s/GRUB_CMDLINE_LINUX=\"/GRUB_CMDLINE_LINUX=\"console=tty0 console=ttyS0,115200n8 /' \
    --run-command "grub2-mkconfig -o /boot/grub2/grub.cfg" \
    --run-command 'growpart /dev/sda 4 || growpart /dev/sda 3' \
    --run-command 'xfs_growfs /' \
    --uninstall cloud-init \

In the virt-customize command, the arguments

--edit '/etc/default/grub: s/GRUB_CMDLINE_LINUX=\"/GRUB_CMDLINE_LINUX=\"console=tty0 console=ttyS0,115200n8 /' \
--run-command "grub2-mkconfig -o /boot/grub2/grub.cfg" \

are used to enable the serial console, which is necessary for us to access the virtual machine through the serial console later.

The argument

--run-command 'growpart /dev/sda 4 || growpart /dev/sda 3'

tries to grow the partition 4 of the disk /dev/sda, which is the root partition in the cloud image. If it fails (e.g., because there are only 3 partitions), it will try to grow partition 3 instead.

Virtual machine creation

To create the virtual machine, we can use the virt-install command. Below is an example of how to do this:

export LIBGUESTFS_BACKEND=direct
VM_NAME=$1
IMAGE_NAME=$2
IMAGE_DIR="/home/vms"
virt-install \
--name "$VM_NAME" \
--ram 4096 \
--vcpus 2 \
--cpu host-passthrough \
--os-variant rocky9 \
--disk path="$IMAGE_DIR/$VM_NAME.qcow2",bus=virtio \
--network network=default \
--import \
--graphics none \
--boot uefi \
--serial pty \
--console pty,target_type=serial \
--noautoconsole

In this example, 4GB of RAM and 2 vCPUs are allocated to the virtual machine.

After creation, if you would like to remove the virtual machine, you can use the virsh undefine command:

virsh undefine "$VM_NAME" --remove-all-storage --nvram

To do this, you need to make sure that the virtual machine is shut down first

Daily operation

To show the console of the virtual machine, we can use the virsh console command:

virsh console "$VM_NAME"

To shut down the virtual machine, we can use the virsh shutdown command:

virsh shutdown "$VM_NAME"
